# Naming proposals

These documents contain recommendations that need a maintainer decision.
Publication does not approve a rename or change released behavior.

| Proposal | Status | Scope |
| --- | --- | --- |
| [001: Product terminology](001-product-terminology.md) | Proposed | Instance, deployment choices, views, and configuration exports. |
| [002: Feature names](002-feature-names.md) | Proposed | Built-in plugins, visual nodes, SDK ownership, and lifecycle terms. |

## Make a proposal

1. Describe the reader's confusion with a concrete example.
2. Define the current object and its behavior.
3. Propose the new term and explain why it fits.
4. List affected interfaces, repositories, and identifiers.
5. Describe compatibility, migration, and alternatives.
6. Link to source evidence and relevant discussions.

Keep the status **Proposed** until a maintainer explicitly accepts or rejects the change.
Record that decision in [decisions](../decisions/README.md).
An accepted name can still require implementation work before it appears in a release.
